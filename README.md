# HWP 문구 대조 — 2026-09-30

문제지와 해설·지문 분석을 브라우저에서 대조하는 도구입니다. AI API나 서버 저장소가 필요하지 않습니다. 파일을 외부로 전송하지 않으며, 수정 HWP를 만들거나 다운로드하지 않습니다.

## GitHub Pages에 올리기

배포 ZIP의 압축을 푼 다음, `index.html`과 CSS·JS 파일을 모두 GitHub 저장소 최상단에 올리세요. 폴더나 ZIP 하나만 올리는 방식이 아닙니다. 기존 파일은 같은 이름으로 교체합니다.

GitHub의 Settings → Pages에서 현재 사용 중인 게시 브랜치와 폴더 설정을 유지합니다. 루트에서 게시 중이면 모든 웹 파일을 루트에 둡니다. 배포가 끝난 뒤 기존 사이트 주소를 새로고침하세요.

사용자의 HWP 문서는 저장소에 올리지 않습니다. `.openai` 설정이나 인증 정보도 필요하지 않습니다.

## 사용 방식

1. 문제지와 해설지 HWP 두 개를 함께 넣습니다. 파일명에서 역할을 구분합니다.
2. 처음에는 전체 문항과 지문 분석을 검사합니다.
3. ‘과학·기술만 보기’를 누르면 `[14~17] (과학)`, `[10~13] 기술` 같은 제목에서 찾은 범위만 표시합니다. 두 분야가 여러 범위에 있으면 함께 포함합니다. 제목이 없으면 임의 범위를 쓰지 않습니다.
4. 왼쪽의 ‘차이 확인 / 번호 확인 / 지문 분석’으로 전환합니다. 번호 확인에는 번호가 붙은 지문 박스의 일치·불일치 결과를 모두 표시합니다. 오른쪽의 글자 버튼 ‘확인 필요 / 전체 검사 항목’은 애매한 대응과 전체 검사 결과를 보여 줍니다. 뜻풀이·분석 설명은 화면과 집계에서 제외합니다.
5. 지문 분석은 원문을 여러 문장으로 된 덩어리로 보여 줍니다. ‘지문 분석’을 선택하면 일치한 덩어리도 함께 보입니다.

## 비교 기준

- 상상 형식의 `N. … 정답` 제목과 서바이벌 형식의 별도 ‘정답 / 해설 / 오답풀이’ 구간을 구분합니다. 서바이벌 오답풀이의 ①·②는 문제지 선지로 취급하지 않습니다.
- 번호가 붙은 지문 박스는 참조 기호를 포함합니다. 해설 인용·지문 분석은 기준 원문의 참조 기호를 제외합니다.
- 공백과 줄바꿈은 무시합니다. 조사·어미·문장부호는 비교합니다.
- 한글 용어에 붙은 한자 병기만 생략을 허용합니다. 예: `산화(酸化)` → `산화`. 다른 한자를 적거나 한자 자체가 본문인 경우까지 무시하지 않습니다.
- 지문 박스의 문구와 `1-3`, `➊-3` 같은 문단·문장 번호를 별도로 확인합니다. 동일 문구의 실제 위치가 다르면 번호를 표시합니다. 복수 후보나 복잡한 선택과목 구조는 확정하지 않고 후보로 표시합니다.
- 여러 문장 인용은 연속된 원문 구간에서 찾습니다. 관련 없는 문장을 임의로 이어 붙여 일치시키지 않습니다.
- 분석지의 화살표·설명용 글머리표 뒤 설명은 원문 일치 검사에서 제외합니다. 화면에서는 원문을 덩어리로 표시하며, 분석 설명은 화면에 표시하지 않습니다.
- 명시적 ‘의미 / 뜻’ 문맥의 뜻풀이는 오류로 잡지 않습니다. 짧은 표현의 인용 여부가 불명확하면 확인 대상으로 남깁니다.

- 칠기모의 독립된 문항 번호와 ‘|정답②’ 제목도 읽습니다. 빠른 정답표는 제외하고, 정답 선지에 번호 기호가 없으면 해당 정답 번호로 연결합니다. 다섯 행이 확인되는 표형 선지도 조합해 비교합니다.

## 확인한 내용

- 제공된 서바이벌 문제지·해설지 전체를 읽고 1~45번 인식, 과학 14~17번 탐지.
- 서바이벌 과학 근거 9개에서 문구와 문장 번호 일치.
- 제공된 상상 자료에서 과학 10~13번 탐지, 과학 분석 원문 24문장을 6개 덩어리로 표시.
- 6번 및 45번의 연속 문장 인용, 이전 11·12번 지문 박스의 ⓑ 누락 회귀 검사.
- 한자 병기 누락 허용, 잘못 적은 한자 검출, 변경 글자의 실제 위치, 잘못된 문장 번호, 여러 과학·기술 범위 및 범위 없음 확인.
- 칠기모 제공 파일의 4~34번, 선지 155개(정답 번호 생략 및 13번 표형 선지 포함) 대조 확인. 해당 파일에는 분야 제목·별도 지문 분석·문장 번호 박스가 없어 임의로 만들지 않습니다. 기술 지문은 문제 번호에 10-13을 입력해 볼 수 있습니다.
- 실제 세 쌍의 파일로 브라우저 동작, 전체 → 분야별 전환, 파일 교체 시 범위 초기화, 모바일 화면 및 외부 요청 없음 확인.

## 한계

HWP 문단 구조와 문장부호로 문단·문장을 추정합니다. 표·대화·각주가 끼어 있거나, 문장부호가 생략되거나, 참조 기호가 그림으로 들어간 경우는 확인이 필요합니다. 분석지의 글머리표가 본문 문자로 추출되지 않는 경우 문장 형태와 원문 일치를 함께 이용하며, 모든 편집 형식의 경계를 보장하지 않습니다. 의미의 타당성, 수식·그림 속 글자는 검사하지 않습니다. HWPX 및 암호·배포용·보호 HWP는 지원하지 않습니다. 파일당 20MB까지 지원합니다.

## 코드 구성

- `index.html`: 화면과 파일 연결
- `style.css`, `review.css`: 디자인과 덩어리 표시
- `app.js`: 파일 읽기, 전체 검사, 범위·분류 필터, 결과 표시
- `compare.js`: 글자 대조·위치 매핑·공통 함수
- `review.js`: 해설 형식 해석, 인용·박스·분석 분류, 한자 병기, 문장 번호, 분야 탐지
- `hwp.js`: HWP 5.x 읽기. 기존 서식 저장 함수는 남아 있으나 화면에서 호출하지 않습니다.
- `pako.min.js`, `PAKO-LICENSE.txt`: 압축 처리 라이브러리와 라이선스

로컬에서 실행하려면 위 파일들이 있는 폴더에서 `python -m http.server 8765`를 실행하고 `http://localhost:8765`를 여세요. GitHub Pages로 배포하면 방문자의 별도 설치나 로그인 없이 사용할 수 있습니다.

HWP 공개 명세 및 rhwp 구현을 참고했습니다. pako는 포함된 라이선스를 따릅니다.

- 짧은 인용과 긴 원문 문장 전체의 유사도만 비교하던 문제를 보완했습니다. 원문 내부의 대응 구간을 찾고, 인용 범위 밖의 앞뒤 내용은 제외합니다. 비슷한 후보가 여러 개이면 대응을 확정하지 않습니다.

- 실제 칠기모 HWP로 브라우저 표시를 확인했습니다. 기존 상상·서바이벌은 이전에 추출해 보관한 본문으로 회귀 검사를 진행했습니다.
